# Publishing checklist

Rules that decide whether **CoworkingView for Calc** (`com.coworkingview.calc`, 0.1.0) can be installed and can stay listed on [extensions.libreoffice.org](https://extensions.libreoffice.org). Each row is a rule, how this package meets it, the source, and what would get it rejected or pulled.

The current site replaced the old Plone workflow. Where the two disagree, this checklist follows the current maintainer guide and the release tables of extensions updated in 2024 and 2025. The older documents are still the spec for `description.xml`, which LibreOffice itself reads.

## How an entry is created now

| Rule | How we meet it | Source | Rejection risk |
|---|---|---|---|
| A TDF single sign-on account is required. Questions go to the extensions forum, not to a private mail thread. | Documented here. Nobody can upload from this repository; a person with the account has to. | [Using this site as an extension maintainer](https://extensions.libreoffice.org/en/home/using-this-site-as-an-extension-maintainer) | No account, no upload. |
| The English entry is the primary entry and the fallback for every other language. Pick English in the language menu and save that before translating. | All `description.xml` strings and both description files are `lang="en"`. [LISTING.md](LISTING.md) is the English paste. No half-translated fields. | Same maintainer guide, "Creating a new entry" and "Translating your extension entries". | An entry whose first save is not English is a bad fallback. The guide says the grey label means English is still standing in. |
| Tags are chosen so the extension can be found without knowing its name. Moderators translate tags. Do not submit a translated tag list. | Tags copied from a Calc-function listing: Calc, Spreadsheets, Extensions, Business. | Maintainer guide. Tag set as shown on [Lox365](https://extensions.libreoffice.org/en/extensions/show/27434). | Vague or unrelated tags (Writer, Draw) hide it or look like the wrong component. |
| Homepage and source repository URLs are separate fields, and the description still contains a `Homepage:` line. | Homepage field and the line are both `https://coworkingview.com`. Repository field is the GitHub project. [Pandas for LibreOffice](https://extensions.libreoffice.org/en/extensions/show/41998) puts both lines in the description. | Maintainer guide; Lox365 and Pandas description text. | A description with no homepage line is how several older pages read once the dedicated field is easy to miss. Lox365's page is the pattern we copied. |
| Save the entry before adding a release file. | [LISTING.md](LISTING.md) says save, then upload. | Maintainer guide: "Before you can add files for download, you have to save the Extension's entry first." | The form will not take the `.oxt` until the entry exists. |
| After Publish, a moderator handles the request. | Called out in the listing. Nothing in the package tries to look pre-approved. | Maintainer guide, last paragraph of "Translating your extension entries". | Publishing an empty license, a broken zip, or a non-English primary entry is what a moderator sends back. |
| The old "submit for approval, then you may add a release" flow, and the "language must be neutral or the project is invisible" warning, are the previous site. | We do not wait for an approval state before uploading, and we do not set a language-neutral flag. English is the primary language instead. | Outdated: [Publishing Extensions in LibreOffice (PDF)](https://wiki.documentfoundation.org/images/1/14/Publishing_extensions.pdf). Current: the maintainer guide and [the 2023 site announcement](https://blog.documentfoundation.org/blog/2023/07/27/try-our-updated-extensions-and-templates-site/). | Following the PDF literally blocks the upload or hides the page. |

## The release row

Taken from the tables on Lox365 (2024-10-16), Pandas for LibreOffice (2025-01-08) and LibrePythonista (2025-08-05). Columns actually shown: Release, Description, Compatibility, Operating Systems, License, Release notes, Updated, Download.

| Rule | How we meet it | Source | Rejection risk |
|---|---|---|---|
| Compatibility is the minimum LibreOffice version, written the way current rows write it (`7.0`, not a micro version). | Release compatibility `7.0`. The package says `<lo:LibreOffice-minimal-version value="7.0" lo:name="LibreOffice 7.0"/>`. There is no maximum, so 7.x, 24.x, 25.x and later stay installable. | Release tables above. Two-part version and `lo:name`: Andreas Mantke, *Erweiterungen für LibreOffice erstellen*, 28 April 2024, [PDF](https://amantke.de/wp-content/uploads/2024/04/extensionbook_2024_04.pdf), chapter 2. The book says a maximum LibreOffice version can no longer be set. | `7.0.0` or `24.2.7` as the minimum makes the dependency stricter than the form and can fail the "two-part value" rule in the book. A maximum version would refuse newer LibreOffice. |
| Operating systems on the form are Linux, Windows and macOS, ticked separately. | All three. The package itself uses `<platform value="all"/>` so one file installs on every architecture, including Apple Silicon and Linux arm64. | Release tables. `platform value="all"`: 2024 book, chapter 2. The book's token table has no `macosx_aarch64`. An empty platform value installs on no operating system (same chapter). | Listing only `linux_x86_64,windows_x86_64,macosx_x86_64` inside `description.xml` refuses the install on arm64. Leaving `value` empty refuses every install. |
| License on the form is a named licence the site already shows. | `MIT`. The same text is in `LICENSE` and in `registration/license.txt`, and the Extension Manager shows it (`accept-by="user"`). | MIT on [Pandas](https://extensions.libreoffice.org/en/extensions/show/41998) (2025-01-08) and [Office 2003 Blue Theme](https://extensions.libreoffice.org/en/extensions/show/99300) (2025-06-22, including a 25.8 row). | An empty license file installs as a blank license page. The 2024 book says to fill the file before publishing. A proprietary licence is outside what the book says the site is for ("sofern sie unter einer freien Software-Lizenz stehen"). |
| The Download control is the `.oxt` on this site, not only a link to another host. | `./build.sh` writes `dist/coworkingview-calc-0.1.0.oxt`. The listing says to upload that file. | Lox365 review, 1 June 2023, on the same page: "Why isn't the download link here?" The maintainer guide's "Adding releases" is an upload, not a remote URL. | A release whose button leaves the site draws the same complaint and looks unfinished to a moderator. |
| Release notes say what the version changes, in English. | `release-notes/release-notes.en.txt` is also linked from `description.xml`, and the same text is in [LISTING.md](LISTING.md) for the form. | `release-notes` element: [example description.xml](https://wiki.openoffice.org/wiki/Documentation/DevGuide/Extensions/Example). The release-notes column is on every model listing. | A notes field that only says "bugfixes" for a first release does not tell a moderator what the extension does. |

## `description.xml` and the zip

LibreOffice reads these. A package that fails here never reaches a reviewer in a working state.

| Rule | How we meet it | Source | Rejection risk |
|---|---|---|---|
| The file is a zip whose name ends in `.oxt`, and `description.xml` is at the root of the zip, not inside a folder. | `build.sh` zips the stage directory and then checks the entry names. | 2024 book, chapter 2. [File format](https://wiki.openoffice.org/wiki/Documentation/DevGuide/Extensions/File_Format). | A zip of the parent folder ("`coworkingview-calc/description.xml`") is reported as not a valid extension. |
| `META-INF/manifest.xml` exists. | It registers the type library, `CalcAddIns.xcu`, and the Python component. | 2024 book, chapter 2: without `manifest.xml` the extension can install and then fail to uninstall. | A missing manifest is the uninstall error in that chapter. |
| Identifier is unique and stable. | `com.coworkingview.calc`. | [Description of XML elements](https://wiki.openoffice.org/wiki/Documentation/DevGuide/Extensions/Description_of_XML_Elements), `/description/identifier`. The 2024 book: two packages with the same identifier cannot both be installed, and the identifier is what an update feed keys on. | A second upload with a different identifier splits the listing. Reusing someone else's identifier collides in Extension Manager. |
| Version is dotted numbers. `0.1.0` is allowed. | `0.1.0` in `description.xml`, the Python module, the `.oxt` file name, and the release row. | 2024 book: the example version is `0.1.3`. | A version that is not dotted numbers is rejected by Extension Manager. |
| Publisher name and a required URL. | Name `CoworkingView`, `xlink:href="https://coworkingview.com"`, `lang="en"`. No `www`. | XML elements, `/description/publisher/name`: `xlink:href` and `lang` are required. Shown in Extension Manager on the right of the entry (2024 book, chapter 2). | A publisher with no URL fails the schema. A `www` host is the wrong canonical site for this project. |
| Display name, English. | `CoworkingView for Calc`. | XML elements, `/description/display-name`. The string must not be empty or only whitespace. | The file name is shown instead, which is a poor listing title. |
| Icon, PNG, default and high contrast. | `icons/icon.png` and `icons/icon_hc.png`, both 128×128, cropped from `icons/coworkingview-mark.png`. | XML elements, `/description/icon`. The 2024 book draws the example at 42×42. | A missing icon is the blank slot in the book's figure. A red square is the placeholder this project must not ship. 128×128 is a deliberate step away from the book's 42×42 example: the wordmark is not readable at 42×42, and Extension Manager scales a PNG. That is not a schema failure. |
| Extension description file, English, linked by relative URL. | `pkg-description/pkg-description.en` includes `Homepage: https://coworkingview.com`. | XML elements, `/description/extension-description`. The 2023 Python extension post uses this exact path: [LibreOffice extensions with Python, part 1](https://dev.blog.documentfoundation.org/2023/11/25/libreoffice-extensions-with-python-part-1/). | A description that points at a missing file shows an empty pane in Extension Manager. |
| License text is real and is shown to the user. | `registration/license.txt` is the MIT licence plus the note that API data is not under that licence. `accept-by="user"`, `suppress-on-update="true"`. | XML elements, `/description/registration`. 2024 book: an empty license file is a blank page, and that is not publishable. `suppress-on-update` is the attribute that book documents. | An admin-only accept (`accept-by="admin"`) hides the licence from the person installing into their own profile. |
| Minimal LibreOffice version uses the LibreOffice 2011 namespace, not `OpenOffice.org-minimal-version` with a 7.x value. | `xmlns:lo="http://libreoffice.org/extensions/description/2011"` and `lo:LibreOffice-minimal-version`. | 2024 book, chapter 2. The OpenOffice.org element is documented for OpenOffice.org versions on [the XML element page](https://wiki.openoffice.org/wiki/Documentation/DevGuide/Extensions/Description_of_XML_Elements) and is the wrong dial for "LibreOffice 7.0". | `OpenOffice.org-minimal-version` value `7.0` is compared against the old OpenOffice.org version line. Reports against current LibreOffice include install rejection (for example [mcp-libre issue 16](https://github.com/patrup/mcp-libre/issues/16)). |
| No remote update URL until the extensions site has a stable download URL for this identifier. | `description.xml` has no `update-information` element. Release notes are inside the package. | [Online update](https://wiki.openoffice.org/wiki/Documentation/DevGuide/Extensions/Online_Update_of_Extensions) needs a URL that returns update XML. In 2014 the extensions site did not answer that request usefully ([list post](https://lists.freedesktop.org/archives/libreoffice/2014-December/065451.html)); in 2019 an update still required an explicit element ([list post](https://listarchives.libreoffice.org/fr/discuss/2019/msg00047.html)). | A placeholder URL makes Extension Manager report a failed update check, which looks broken in a review. Add the element in a later version once the file URL exists. |
| The namespace on the root element is the 2006 description namespace, and `xlink` is declared. | Both are on the root. A typo here is the install error in the 2024 book, figure 2.1. | XML elements; 2024 book. | A mistyped namespace aborts installation. |

## Calc functions

| Rule | How we meet it | Source | Rejection risk |
|---|---|---|---|
| A Python extension has `description.xml`, `META-INF/manifest.xml`, `pkg-description/pkg-description.en`, `registration/license.txt`, and a Python file named in the manifest. The component defines `g_ImplementationHelper`. | All of those files are in the `.oxt`. `coworkingview_calc.py` registers `com.coworkingview.calc.CoworkingView`. | [LibreOffice extensions with Python, part 1](https://dev.blog.documentfoundation.org/2023/11/25/libreoffice-extensions-with-python-part-1/) (25 November 2023). The loader looks up `g_ImplementationHelper` in `/usr/lib/libreoffice/program/pythonloader.py`. | A macro under `Scripts/python` would not appear as a spreadsheet function. |
| Spreadsheet functions need an IDL service, a `types.rdb`, and `CalcAddIns.xcu`. Parameter names have no underscores. The category is `Add-In`. | `idl/XCoworkingView.idl`, built into `types.rdb` by `unoidl-write`. Parameter names are `City`, `Product`, `Stat`. Compatibility names are `CWV_SPACES` and the other function names. | [Calc Add-In project type](https://wiki.openoffice.org/wiki/Calc/Add-In/Project_Type) for the xcu shape. Underscores in parameter names are rejected by Calc ([qf-localc build notes](https://github.com/qalydon/qf-localc/blob/master/build.py)). `XAddIn` method `getProgrammaticFuntionName` keeps the historical spelling ([the interface in LibreOffice 24.2's `offapi.rdb`](https://wiki.openoffice.org/wiki/Documentation/DevGuide/Spreadsheets/Spreadsheet_Add-Ins)). | Functions that are not in the type library never show up in the wizard. An underscore in `City` makes the argument fail to register. |
| The Python inside LibreOffice has no pip packages. | `urllib` only. No third-party import. | The 2023 Python post notes that extensions run on LibreOffice's own interpreter. | An import of `requests` or `pandas` installs and then fails on a normal LibreOffice. Pandas for LibreOffice exists as a separate extension for that reason. |
| No network call while the extension is loaded or imported. | `Client` is created on the first formula. `CWV_SOURCE()` does not call the network. | Same expectation as the other clients in this repository (`spec/SPEC.md` section 2). | A call at import makes Calc hang at startup and makes the headless test flaky. |

## Data, privacy, and the icon

| Rule | How we meet it | Source | Rejection risk |
|---|---|---|---|
| Only describe numbers the public API returns. | Field mapping is in the [README](../README.md), from live `GET /v1/market/rates` and `GET /v1/properties` on 2026-11-01. `CWV_SPACES` is `meta.pagination.total`. `CWV_PRICE` is `median.amount`. A missing `p25` is an error. | The responses themselves. The shared contract is `spec/SPEC.md`. | Publishing a function that invents a city, a product, or a zero for a missing statistic is a false listing. Berlin's catalogue total and the price-index `propertyCount` are different numbers; swapping them would be wrong. |
| Do not ship the workspace catalogue. | One properties request, `pageSize=1`. The listing body is dropped before the memory cache. No titles, photos, logos, or operator prices are returned. | The `catalogueNotice` on `GET /v1/properties`. | Caching or returning listings would breach that notice and the "no catalogue copy" claim on the listing. |
| The price index stays attributed. | `CWV_ATTRIBUTION` returns `data.attribution` unchanged, including the host the API wrote. `CWV_SOURCE` is an extra credit line and does not replace it. | CC BY 4.0, and the `attribution` field on the rates response. | Stripping attribution and shipping only the short credit line is a licence problem for anyone who republishes the figures. |
| Privacy text matches the request. | The city slug is the only user value. `locale=en` is fixed. `CWV_SPACES` also sends `page=1` and `pageSize=1`. | Observed: a rates or properties call without `locale` returns HTTP 400 `VALIDATION_FAILED`. | A privacy note that says "nothing is sent" is false. The listing says the city is sent, and that the locale is fixed. |
| The icon is the CoworkingView wordmark, not a red square. | `icons/coworkingview-mark.png` is the mark already used by the other integrations. `tools/render_icons.py` only crops and scales it. The listing logo is `docs/logo-150.png`. | Maintainer guide: a logo helps search. Older caps: 150×150 teaser on the [OpenOffice.org submission page](https://wiki.openoffice.org/wiki/Extensions/website/submission), and max 150×75 (resized if larger) in the [publishing PDF](https://wiki.documentfoundation.org/images/1/14/Publishing_extensions.pdf). The current maintainer guide does not repeat a pixel cap. | A red square fails a visual check and is the one icon this project must not use. Uploading the 192×192 original can be resized by an old form; `logo-150.png` fits the old 150×150 teaser. |

## Before pressing Publish

1. English entry saved, with the short and long text from [LISTING.md](LISTING.md), including the line `Homepage: https://coworkingview.com`.
2. Tags: Calc, Spreadsheets, Extensions, Business. Category Calc if that control is separate.
3. Homepage `https://coworkingview.com`. Repository `https://github.com/coworkingview/flex-office-data`. Logo `docs/logo-150.png`, linked to the same homepage.
4. Release 0.1.0, compatibility 7.0, Linux + Windows + macOS, license MIT, the `.oxt` uploaded, release notes pasted.
5. Screenshots from [LISTING.md](LISTING.md): `docs/screenshots/sheet-berlin.png`, `docs/screenshots/function-wizard.png`, and `docs/screenshots/extension-manager.png`. They were captured from LibreOffice 24.2.7. Do not replace them with a mock.
6. Install `release/coworkingview-calc-0.1.0.oxt` in Extension Manager on 7.x or 24.x, accept the MIT page, restart, and try `=CWV_SOURCE()` and `=CWV_PRICE("berlin","flex_desk")` (or with `;` where the locale requires it).
7. Confirm the publisher link opens `https://coworkingview.com` and the icon is the wordmark.

The headless job in CI covers the build, `unopkg add`, and the formula results. The three listing screenshots above are the Extension Manager, Function Wizard, and sheet captures.
